# NFT за Telegram Stars — бот @GiftIinkBot

Полноценный бот для групповых чатов: покупатель предлагает продавцу сумму в Telegram Stars за конкретный NFT, продавец принимает или отклоняет предложение, покупатель оплачивает официальный счёт Telegram Stars, NFT передаётся покупателю, а выплата продавцу фиксируется оператором.

Проект написан на Python 3.11+, Aiogram 3, SQLite, python-dotenv.

---

## Сначала прочитайте: честные ограничения Telegram

Это не «имитация» оплаты. Бот использует настоящие счёта Telegram Stars и настоящие методы Telegram Bot API. Но у Bot API есть ограничения, которые нельзя обойти кодом:

1. **Автоматически отправить Stars другому пользователю нельзя.**
   В Bot API нет метода `sendStars` или «выплатить Stars пользователю». Метод `transferBusinessAccountStars` переводит Stars **с бизнес-аккаунта на баланс бота**, а не продавцу. Поэтому выплата продавцу выполняется **вручную оператором** и фиксируется командой `/payout`. Бот не показывает фальшивый «баланс продавца» и не пишет «выплачено», пока оператор реально не выполнил выплату.

2. **Автоматическая передача NFT возможна только через Telegram Business.**
   Если продавец подключил бота в Telegram Business и выдал права на просмотр и передачу подарков, бот может вызвать `transferGift`. Иначе продавец передаёт NFT вручную в приложении Telegram и нажимает «Я передал NFT». Бот проверяет владение до сделки и, когда API доступен, после передачи.

3. **NFT не находится в эскроу у бота.**
   Bot API не позволяет «заморозить» NFT до оплаты. Поэтому схема такая: продавец подтверждает владение → покупатель платит → продавец передаёт NFT → покупатель подтверждает получение. Если продавец не передал NFT, покупатель открывает спор, оператор делает возврат Stars. Это компромисс, а не атомарный обмен.

4. **NFT из TON-блокчейна не поддерживаются.**
   Такие подарки нельзя передать средствами Bot API. Бот обнаружит это при проверке владения и предложит сделку через TON-кошелёк вне бота.

5. **Продавца нужно указать явно.**
   По ссылке `t.me/nft/...` нельзя надёжно получить Telegram `user_id` владельца. Поэтому команду нужно отправить **ответом на сообщение продавца** или добавить `@username` продавца. Это защита от выплаты не тому человеку.

Если вам нужна полностью автоматическая выплата Stars — это невозможно через Bot API. Понадобится отдельный кастодиальный сервис/кошелёк и юридическая модель, либо ручная выплата оператором.

## Что умеет бот

- Работает в группах и супергруппах.
- Понимает команду с упоминанием бота, ссылкой на NFT и суммой Stars.
- Определяет покупателя (автора команды) и продавца (reply или `@username`).
- Создаёт карточку: фото NFT, название и номер, ссылка, сумма, покупатель, срок 48 часов.
- Кнопки на карточке ровно **«Принять»** и **«Отклонить»**.
- «Отклонить» переводит сделку в статус **«Отклонена»** и убирает кнопки. Повторное выполнение невозможно.
- «Принять» проверяет владение NFT и открывает отдельное окно подтверждения с покупателем, ссылкой, суммой к выплате и следующим шагом.
- После подтверждения продавцом создаётся **официальный счёт Telegram Stars**.
- Покупатель оплачивает счёт в Telegram; бот проверяет payload, сумму, валюту, покупателя и срок.
- Защита от повторной оплаты: уникальный `charge_id`, атомарные переходы статусов, отдельная таблица возвратов.
- Поздняя оплата после отмены автоматически возвращается; если возврат не удался — администратор получает критическое уведомление.
- Продавец передаёт NFT автоматически (Telegram Business) или вручную.
- Покупатель подтверждает получение; продавец получает инструкцию и уведомление о выплате.
- Администратор отмечает реальную внешнюю выплату командой `/payout`.
- Споры, возвраты, сверка владения NFT, история событий, статистика.
- Просроченные предложения (48 часов) получают статус **«Истекло»**, кнопки перестают работать.
- Главное меню `/start` с семью разделами: создание предложения, мои предложения, история, уведомления, правила, поддержка, профиль.
- Система из семи ролей: USER, TECH ADMIN, ADMIN, OWNER, SKAM, WORKER, IVAN.
- Серверная проверка прав на каждой команде и каждом callback.
- Технический режим на 12 часов (`/zakrit`) с автоматическим возвратом и `/open`.
- Журнал административных действий, блокировки, предупреждения и временные ограничения.
- Токен хранится только в `.env`, логи редактируются, токен не попадает в исходники.

## Настройка `.env`

Файл `.env` уже создан и содержит выданный токен. **Не выводите его в чат, не публикуйте и не добавляйте в git.** В README и примерах токена нет.

Минимально важные параметры:

```dotenv
BOT_TOKEN=токен_из_BotFather
DATABASE_PATH=data/nft_offers.sqlite3
ADMIN_IDS=
OWNER_ID=
PAYMENT_WINDOW_MINUTES=30
PAYMENTS_ENABLED=false
OPERATOR_PAYOUT_ACK=false
BUSINESS_AUTO_TRANSFER=true
MIN_OFFER_STARS=1
MAX_OFFER_STARS=1000000
TIMEZONE=Europe/Moscow
SUPPORT_CONTACT=
LOG_LEVEL=INFO
```

Пояснения:

- `BOT_TOKEN` — токен бота. Если токен засветился, отзовите его в BotFather (`/revoke`) и вставьте новый.
- `ADMIN_IDS` — числовые Telegram ID администраторов через запятую. Узнать свой ID: команда `/whoami` в личном чате с ботом.
- `OWNER_ID` — **главный ID владельца бота**. Только этот ID получает роль OWNER и право назначать роли. Можно указать несколько ID через запятую в `OWNER_IDS`. Роль OWNER нельзя выдать командой `/setrole`.
- Срок предложения зафиксирован — ровно **48 часов**.
- `PAYMENT_WINDOW_MINUTES` — сколько действует счёт на оплату (по умолчанию 30 минут).
- `PAYMENTS_ENABLED` и `OPERATOR_PAYOUT_ACK` — оба должны быть `true`, иначе приём Stars выключен. Это защита от случайного запуска платежей без настроенного оператора.
- `BUSINESS_AUTO_TRANSFER` — пытаться передавать NFT через Telegram Business.
- `MIN_OFFER_STARS` / `MAX_OFFER_STARS` — лимиты суммы.
- `TIMEZONE` — часовой пояс для дат в карточках.
- `SUPPORT_CONTACT` — необязательный текст поддержки в `/help`.
- `LOG_LEVEL` — `INFO` или `DEBUG`. Токен редактируется даже в DEBUG.

### Почему оплата выключена по умолчанию

Потому что выплата продавцу ручная. Пока в `ADMIN_IDS` нет ни одного ID и флаги не включены, бот не должен принимать реальные Stars. Это осознанная защита, а не ошибка.

## Первый запуск и настройка администратора

1. Запустите бота:

   ```powershell
   .\.venv\Scripts\python.exe main.py
   ```

   или `run.bat`.

2. В личном чате с **@GiftIinkBot** отправьте `/whoami`. Бот покажет ваш числовой ID.

3. Откройте `.env` и укажите свой ID как владельца:

   ```dotenv
   OWNER_ID=ваш_числовой_ID
   ```

   Это единственный способ получить роль OWNER. После перезапуска бот
   автоматически закрепит роль за этим ID.

4. При необходимости укажите администраторов:

   ```dotenv
   ADMIN_IDS=ваш_числовой_ID
   ```

   При первом запуске эти ID получают роль ADMIN (если у них ещё нет
   другой роли). Дальше роли выдаются командой `/setrole`.

5. Включите платежи **только после того, как прочитали раздел о ручных выплатах**:

   ```dotenv
   PAYMENTS_ENABLED=true
   OPERATOR_PAYOUT_ACK=true
   ```

6. Перезапустите бота.

7. Проверьте:

   ```powershell
   .\.venv\Scripts\python.exe check_setup.py
   ```

   Скрипт не печатает токен. Он проверит `.env`, SQLite, парсер, `getMe`, баланс бота и (по желанию) ссылку NFT.

## Запуск

```powershell
cd C:\Users\PC\Desktop\1112
.\.venv\Scripts\python.exe main.py
```

Или двойным щелчком по `run.bat`.

Остановка — `Ctrl+C`.

При старте бот:

- читает `.env`;
- подключается к SQLite;
- проверяет токен через `getMe`;
- запускает worker, который каждые 20 секунд обновляет таймер на карточках, истекает предложения и счета;
- начинает polling.

В логах будет строка вида `Подключение к Telegram проверено: @GiftIinkBot (id=...)`. Токена там нет.

### Автозапуск 24/7 на Windows

В проекте есть готовые скрипты:

| Файл | Что делает |
|---|---|
| `install_24_7_user.bat` | ставит задачу от текущего пользователя, запуск при входе. Без UAC. |
| `install_24_7.bat` | ставит задачу от `SYSTEM`, запуск при загрузке и входе. Нужен UAC. Работает даже до входа в Windows. |
| `status_24_7.bat` | показывает состояние задачи, PID и последние строки логов. |
| `stop_24_7.bat` | останавливает бота, но оставляет задачу автозапуска. |
| `uninstall_24_7.bat` | останавливает бота и удаляет задачу автозапуска. |
| `disable_sleep.bat` | отключает сон и гибернацию при питании от сети. |

Логи:

```text
logs\bot.log          # основной лог, ротация 5 МБ x 5
logs\supervisor.log   # запуск/перезапуск/коды выхода
logs\bot.pid          # PID текущего процесса
```

Бот не запускается дважды: второй процесс завершится с сообщением о занятом экземпляре. При падении процесса супервизор перезапускает его через 10 секунд.

Для работы 24/7 компьютер должен быть включён, а сон — отключён. Если нужен запуск до входа в Windows, используйте `install_24_7.bat` от администратора.

### Деплой на Render (бесплатный план)

В проекте есть `render.yaml` (Blueprint) и `DEPLOY_RENDER.md` с пошаговой инструкцией.

- Бот запускается как **Web Service** и одновременно слушает `PORT` — health-check `/health`.
- На Free-плане сервис засыпает после ~15 минут без HTTP-запросов, поэтому нужен внешний пинг `/health` каждые 5–10 минут.
- Диск на Free эфемерный: SQLite обнуляется при деплое/рестарте. Для постоянного хранения нужен платный Persistent Disk или внешняя БД.
- `BOT_TOKEN` задаётся в Render как секрет, в репозиторий не попадает.
- `OWNER_ID=5809580581` уже прописан в `render.yaml`.

Подробности — в `DEPLOY_RENDER.md`.

## Главное меню и роли

### Команда `/start`

В личном чате бот присылает приветствие и меню с кнопками:

1. Создать предложение
2. Мои предложения
3. История сделок
4. Уведомления
5. Правила обмена
6. Поддержка
7. Мой профиль

Все кнопки рабочие. «Мой профиль» показывает ID, username, роль, дату
регистрации и число завершённых сделок. «Мои предложения» и «История сделок»
дают кнопки перехода к деталям сделки. «Уведомления» показывают последние
уведомления и позволяют выключить или включить уведомления о новых
предложениях.

В группе `/start` по-прежнему показывает короткую справку, чтобы не засорять чат.

### Семь ролей

| Роль | Что может |
|---|---|
| **USER** | Создавать предложения, смотреть свои предложения, историю, профиль, правила, поддержку. |
| **WORKER** | Всё то же, что USER. Отличие только в названии. |
| **TECH ADMIN** | Все права USER + `/userinfo`, `/ban`, `/unban`, `/warnings`, `/warn`, `/untimeout`, `/active`, `/errors`. Не получает команды ADMIN. |
| **ADMIN** | Все права USER + `/stats`, `/users`, `/dealsstats`, `/broadcast`, `/settings`. Не получает команды TECH ADMIN. |
| **IVAN** | То же, что ADMIN. Отображается как «IVAN (Иван)». Не может управлять ролями и техрежимом. |
| **OWNER** | Все права USER, TECH ADMIN, ADMIN + `/setrole`, `/removerole`, `/admins`, `/backup`, `/maintenance`, `/zakrit`, `/open`, `/adminlog`. Только OWNER назначает роли. |
| **SKAM** | Функции бота запрещены. `/start` показывает информацию об ограничении. При попытке создать предложение в группе бот пишет нейтральное предупреждение. |

Новый пользователь автоматически получает USER. Роль хранится в SQLite.

### Как задать OWNER ID

1. В личном чате с ботом отправьте `/whoami` — бот покажет числовой ID.
2. Откройте `.env` и добавьте:

   ```dotenv
   OWNER_ID=123456789
   ```

   Несколько владельцев:

   ```dotenv
   OWNER_IDS=123456789,987654321
   ```

3. Перезапустите бота. В логе будет предупреждение, если OWNER не задан.

ID OWNER — единственный источник роли OWNER. Если у пользователя в базе
оказалась роль OWNER, но его ID нет в конфигурации, при следующем действии
роль автоматически сбрасывается на USER.

### Команда `/comand`

Показывает список команд, доступных текущей роли. OWNER видит все четыре
группы: USER/WORKER, TECH ADMIN, ADMIN/IVAN и OWNER. SKAM получает только
сообщение об ограничении.

### Назначение ролей (только OWNER)

```text
/roles 123456789 ADMIN
/roles @username TECH ADMIN
/roles @username IVAN
/roles @username SKAM
/roles @username USER        # снять роль
/roles                       # список ролей и количество пользователей

/setrole 123456789 TECH ADMIN
/setrole @username ADMIN
/setrole 123456789 IVAN
/setrole 123456789 SKAM
/setrole 123456789 WORKER
/removerole 123456789
/admins
```

`/roles` — основной способ: работает и по числовому ID, и по `@username`.
Команда доступна только OWNER. Нельзя назначить OWNER через `/roles` или
`/setrole`, нельзя менять роль OWNER из конфигурации и нельзя повысить самого
себя. Все действия пишутся в `admin_log` и доступны в `/adminlog`.

### Блокировки и предупреждения (TECH ADMIN)

```text
/userinfo 123456789
/ban 123456789 спам
/unban 123456789
/warnings 123456789
/warn 123456789 Нарушение правил
/warn 123456789 24 Временное ограничение на сутки
/untimeout 123456789
/active
/errors
```

Заблокированный пользователь не может пользоваться ботом. Временное
ограничение действует до указанного срока и снимается автоматически.

### Статистика и рассылка (ADMIN / IVAN)

```text
/stats
/users
/dealsstats
/broadcast Внимание: обновлены правила обмена
/settings
/settings support_contact @support
/settings min_offer_stars 10
/settings max_offer_stars 100000
```

`/broadcast` отправляет текст всем зарегистрированным пользователям и
показывает число доставленных и недоставленных сообщений.

### Технический режим (только OWNER)

```text
/zakrit              # выключить на 12 часов
/open                # включить досрочно
/maintenance on      # включить без срока
/maintenance off     # выключить
```

Во время техрежима обычные пользователи получают:

> Бот временно находится на техническом обслуживании. Попробуйте позже.

Состояние хранится в SQLite (`service_state`), поэтому переживает перезапуск.
Через 12 часов бот включается автоматически. ADMIN, IVAN и TECH ADMIN не
могут отменить техрежим: для этого нужно право OWNER.

### Журнал и резервные копии

```text
/adminlog
/backup
```

`/backup` создаёт копию SQLite в папке `backups/` и отправляет файл OWNER.
Административные действия хранятся в таблице `admin_log`.

### Проверка доступа

Права проверяются на сервере при каждом сообщении, команде и callback:

- middleware блокирует SKAM, бан, временное ограничение и техрежим;
- каждая команда заново читает роль из SQLite;
- callback проверяет участие в сделке и роль;
- при нехватке прав выводится: «У вас недостаточно прав для выполнения этого действия».

Скрытие кнопок не считается защитой.

Боту не нужно читать все сообщения группы: команда содержит упоминание бота, а ответ на сообщение продавца приходит вместе с командой. Поэтому privacy mode можно не отключать.

Если бот не видит команду:

1. В BotFather: `/setprivacy` → выберите бота → **Disable**.

Отключение privacy означает, что бот технически видит больше сообщений группы. Делайте это осознанно.

## Как создать предложение

Покупатель — автор команды. Продавец — тот, на чьё сообщение ответили, или тот, кого указали через `@username`.

### Вариант 1 — ответ на сообщение продавца (рекомендуется)

В группе ответьте на сообщение продавца:

```text
@GiftIinkBot https://t.me/nft/PlushPepe-1 100
```

Где `100` — сколько Stars предлагает покупатель.

### Вариант 2 — явное указание продавца

```text
@GiftIinkBot @seller https://t.me/nft/PlushPepe-1 100
```

### Вариант 3 — команда `/offer`

Ответом на сообщение продавца:

```text
/offer@GiftIinkBot https://t.me/nft/PlushPepe-1 100
```

или с явным продавцом:

```text
/offer@GiftIinkBot @seller https://t.me/nft/PlushPepe-1 100
```

(в личном чате предложение создать нельзя — только в группе).

### Почему нельзя просто «ссылка + сумма» без продавца

Ссылка `t.me/nft/...` не содержит Telegram ID владельца. Определить владельца по странице можно только как отображаемое имя, и это ненадёжно. Чтобы не отправить выплату случайному человеку, бот требует reply или `@username`. Это важно для безопасности.

### Ограничения команды

- Сумма — целое число Stars в пределах `MIN_OFFER_STARS..MAX_OFFER_STARS`.
- В команде должно быть ровно одно число (кроме цифр в ссылке и username).
- Нельзя предложить самому себе.
- Нельзя создать второе активное предложение на тот же NFT тому же продавцу.
- Анонимные сообщения от имени канала не принимаются — нужен личный аккаунт.

## Что происходит после команды

Бот отправляет в группу карточку с текстом:

```text
@pasha4373 предлагает Вам 100 звёзд за подарок Plush Pepe #12345.
Предложение действует ещё 48ч 00м.
```

- Username подставляется из аккаунта покупателя.
- Сумма берётся из команды.

Если фото отправить не удалось, бот отправит текстовую карточку с тем же текстом.

## Полный сценарий сделки

### 1. Продавец нажимает «Отклонить»

- Статус: **«Отклонена»**.
- Кнопки исчезают.
- Покупатель получает уведомление.
- Повторно принять/отклонить нельзя: переход статуса атомарный.

### 2. Продавец нажимает «Принять»

- Бот проверяет, что именно этот пользователь — продавец.
- Бот проверяет, что NFT действительно есть у продавца (`getUserGifts` или Business).
- Проверяет, что NFT можно передать: не сожжён, не из TON-блокчейна, нет запрета, не истёк срок блокировки передачи.
- Статус: **«Принято, ожидает подтверждения»**.
- В группе обновляется карточка.
- Продавцу в личные сообщения приходит **отдельное окно подтверждения**: покупатель, ссылка, сумма к выплате, комиссия (если есть), следующие шаги и кнопка **«Подтвердить сделку»**.
- Если личка закрыта, окно с кнопкой отправляется в группу.

### 3. Продавец нажимает «Подтвердить сделку»

- Бот ещё раз проверяет владение NFT.
- Создаёт официальный счёт Telegram Stars через `createInvoiceLink` (валюта XTR).
- Статус: **«Ожидает оплаты»**.
- Счёт действует `PAYMENT_WINDOW_MINUTES` (по умолчанию 30 минут).
- Покупатель получает счёт в личку; если личка закрыта — в группу.
- Счёт можно оплатить только с аккаунта покупателя: бот проверяет `from_user.id` на pre-checkout.

### 4. Покупатель оплачивает

- Telegram присылает боту `successful_payment`.
- Бот проверяет payload, nonce, валюту XTR, сумму, покупателя.
- Записывает `charge_id` в `payment_charges` (уникальный индекс).
- Статус: **«Оплачено, ожидает передачи NFT»**.
- Покупатель получает подтверждение.
- Продавец получает инструкцию передать NFT и кнопку **«Я передал NFT»**.
- Если включена автопередача Business — бот пытается передать NFT сам.

### 5. Передача NFT

**Автоматически (Telegram Business):**

- Бот вызывает `transferGift`.
- Если у продавца есть комиссия за передачу, она списывается с бизнес-баланса продавца; бот показывает её заранее.
- Бот проверяет, появился ли NFT у покупателя.
- Статус: **«NFT передан, ожидает подтверждения»**.
- Покупатель получает кнопку **«Подтвердить получение»**.

**Вручную:**

- Продавец передаёт NFT в приложении Telegram.
- Нажимает **«Я передал NFT»**.
- Бот пытается проверить NFT у покупателя; если API недоступен, покупатель всё равно может подтвердить получение.
- Статус: **«NFT передан, ожидает подтверждения»**.

### 6. Покупатель подтверждает получение

- Статус: **«Получение подтверждено, ожидает выплаты»**.
- Продавец получает сообщение: к выплате столько-то Stars, выплата выполняется оператором.
- Администраторы получают уведомление с командой `/payout`.
- Бот **не** пишет «Stars отправлены», потому что Bot API этого не умеет.

### 7. Оператор выплачивает Stars

Оператор реально переводит продавцу согласованную сумму (см. раздел ниже) и фиксирует:

```text
/payout 12 ССЫЛКА_ИЛИ_НОМЕР_ВЫПЛАТЫ
```

- Статус: **«Завершена»**.
- Продавец получает подтверждение с ссылкой/номером.
- Покупатель получает сообщение о завершении.

## Telegram Business и автопередача NFT

Автопередача работает только если продавец — владелец бизнес-аккаунта Telegram Business и подключил бота как бизнес-бота.

### Как подключить (продавец)

1. Telegram → **Настройки** → **Telegram Business**.
2. **Чат-боты** → добавьте **@GiftIinkBot**.
3. Выдайте права:
   - **Просмотр подарков и Stars** (`can_view_gifts_and_stars`);
   - **Передача и улучшение подарков** (`can_transfer_and_upgrade_gifts`);
   - если у NFT есть комиссия за передачу — **Передача Stars** (`can_transfer_stars`).
4. Проверьте статус командой `/business` в личном чате с ботом.

Бот получит `business_connection` и сохранит права в SQLite.

### Что важно

- Комиссия за передачу NFT, если она есть, списывается с бизнес-баланса продавца, а не с покупателя.
- Если прав нет, бот не будет пытаться автопередачу: продавец передаст NFT вручную.
- Если автопередача упала с ошибкой, сделка возвращается в статус «Оплачено», продавец получает кнопку ручной передачи, администраторы — уведомление.
- `transferBusinessAccountStars` **не** используется для выплаты продавцу: этот метод переводит Stars с бизнес-аккаунта **боту**, а не наоборот.

## Ручная выплата продавцу

Это единственный честный способ выплатить Stars при текущем Bot API.

1. Покупатель подтвердил получение NFT.
2. Бот показывает статус «Ожидает выплаты» и присылает администратору команду `/payout`.
3. Оператор проверяет сделку:

   ```text
   /deal 12
   /pending
   ```

4. Оператор переводит продавцу согласованную сумму одним из способов:
   - из собственного баланса Telegram Stars (если доступно в регионе);
   - через вывод Stars бота в TON (Fragment) и последующий расчёт с продавцом;
   - иным согласованным способом (USDT/TON/перевод), если стороны так договорились.
5. Оператор фиксирует факт выплаты:

   ```text
   /payout 12 https://t.me/... или номер_транзакции
   ```

6. Бот сохраняет ссылку/номер, переводит сделку в «Завершена» и уведомляет стороны.

**Бот не хранит баланс продавца и не показывает фальшивые «выплачено».** Пока оператор не выполнил `/payout`, статус остаётся «Ожидает выплаты».

### Сколько ждать вывод Stars бота

Telegram может удерживать Stars бота перед выводом (обычно до 21 дня). Это ограничение Telegram, а не бота. Если продавцу нужно заплатить раньше, оператор может использовать собственные средства, а затем вывести баланс бота, когда Telegram разрешит.

## Возвраты и споры

### Автоматический возврат поздней оплаты

Если покупатель оплатил счёт после того, как сделка была отменена по таймауту:

- бот видит, что оплата не может быть зачтена;
- вызывает `refundStarPayment`;
- пишет покупателю, что Stars возвращены;
- записывает возврат в таблицу `refunds`, чтобы не вернуть дважды;
- если возврат не удался — администраторы получают критическое уведомление с `charge_id`.

### Ручной возврат

Администратор в личном чате:

```text
/refund 12
```

- Возврат возможен из статусов «Оплачено», «Передача NFT», «NFT передан», «Ожидает выплаты», «Спор».
- Нельзя вернуть из «Завершена», «Возврат выполнен», «Отменена», «Отклонена», «Истекло».
- Повторный возврат по тому же `charge_id` блокируется.

### Спор

Любая сторона может нажать «Проблема» на этапе после оплаты. Бот:

- переводит сделку в **«Спор, ожидает оператора»**;
- уведомляет администраторов;
- показывает карточку со статусом спора.

Оператор изучает переписку, проверяет NFT командой `/reconcile 12`, затем либо `/refund 12`, либо `/payout 12 ССЫЛКА`.

### Сверка NFT

```text
/reconcile 12
```

Бот проверяет, есть ли NFT у покупателя. Если да — переводит сделку в «NFT передан» и просит покупателя подтвердить. Это помогает, если продавец передал NFT, но статус не обновился.

| Статус в БД | Подпись |
|---|---|
| `pending` | Ожидает решения |
| `accepted` | Принято, ожидает подтверждения |

## Диагностика

### Бот не отвечает в группе

1. Проверьте, что бот добавлен в группу.
2. Проверьте, что команда содержит `@GiftIinkBot` или является `/offer@GiftIinkBot`.
3. Если не видит — отключите privacy mode в BotFather и перезайдите в группу.
4. Проверьте, что у бота есть право отправлять сообщения.

### «Не удалось определить продавца»

Ответьте командой на сообщение продавца или добавьте `@username`:

```text
@GiftIinkBot @seller https://t.me/nft/PlushPepe-1 100
```

### «NFT с таким именем не найден»

- Проверьте, что NFT действительно на аккаунте продавца.
- Проверьте, что ссылка вида `https://t.me/nft/Name-123`.
- Если NFT в Telegram Business, подключите бота в Business и выдайте права.
- Если NFT из TON-блокчейна — Bot API не может его передать.

### «Оплата Stars отключена»

В `.env` должны быть одновременно:

```dotenv
ADMIN_IDS=ваш_ID
PAYMENTS_ENABLED=true
OPERATOR_PAYOUT_ACK=true
```

Перезапустите бота.

### «Не удалось создать счёт Telegram Stars»

- Проверьте, что токен действителен.
- Проверьте интернет.
- Попробуйте позже; Telegram может временно отклонять создание счёта.
- В логах будет причина без токена.

### Счёт оплачен, но статус не изменился

Telegram присылает `successful_payment` с задержкой. Подождите несколько секунд. Если статус не меняется:

- проверьте логи;
- проверьте, что бот запущен;
- не оплачивайте повторно;
- администратор может проверить `/deal НОМЕР`;
- при необходимости `/refund НОМЕР`.

### Продавец не может принять

- Он должен быть тем самым продавцом (reply/`@username`).
- NFT должен быть у него.
- NFT не должен быть из TON-блокчейна или сожжён.
- Передача не должна быть заблокирована до будущей даты.
- Для создания счёта после подтверждения должны быть включены платежи (`ADMIN_IDS`, `PAYMENTS_ENABLED`, `OPERATOR_PAYOUT_ACK`).

### Ошибка «message is not modified»

Это не ошибка: бот попытался обновить карточку тем же текстом. Она игнорируется.

   ```text
   @GiftIinkBot https://t.me/nft/PlushPepe-1 100
   ```

4. Бот присылает карточку с фото, названием, ссылкой, суммой, покупателем, сроком и кнопками **«Принять»** / **«Отклонить»**.
5. Продавец нажимает **«Отклонить»** — карточка становится «Отклонена», кнопки исчезают, повторное нажатие невозможно.
6. Для второй демонстрации создайте новое предложение.
7. Продавец нажимает **«Принять»** — в группе появляется статус «Принято», а продавцу в личку приходит отдельное окно подтверждения с покупателем, ссылкой, суммой к выплате и кнопкой **«Подтвердить сделку»**.
8. Продавец подтверждает — покупатель получает официальный счёт Telegram Stars.
9. Покупатель оплачивает (для реальной демонстрации — минимальную сумму; для записи без трат можно остановиться на счёте).
10. После оплаты продавец передаёт NFT (вручную или автоматически через Business).
11. Покупатель подтверждает получение.
12. Администратор делает `/payout` и показывает финальный статус «Завершена».

Для демонстрации без реальных трат: не включайте `PAYMENTS_ENABLED` и покажите карточку, принятие, окно подтверждения и отказ. Кнопка «Подтвердить сделку» в этом режиме честно сообщит, что приём Stars выключен, и счёт не будет создан. Не имитируйте оплату — бот не покажет фальшивое «оплачено».

## Частые вопросы

**Можно ли автоматически выплатить Stars продавцу?**
Нет. В Bot API нет метода отправки Stars другому пользователю. Выплата — вручную оператором, с фиксацией через `/payout`.

**Можно ли автоматически передать NFT?**
Да, если продавец подключил Telegram Business и выдал права. Иначе — вручную.

**Почему продавец должен подтверждать сделку после «Принять»?**
Чтобы показать отдельное окно с условиями и получить явное согласие перед созданием счёта. Это также защита от случайного нажатия.

**Почему нельзя создать предложение в личке?**
Сделка публичная: карточка и кнопки должны быть в группе, чтобы обе стороны видели условия. Личка используется для счетов, уведомлений и админ-команд.

**Что если продавец не передаст NFT после оплаты?**
Покупатель открывает спор. Оператор делает `/refund`, Stars возвращаются покупателю. NFT не в эскроу — это ограничение Bot API.

**Где хранится токен?**
Только в `.env`. В коде, README и логах его нет.

**Можно ли запустить на сервере?**
Да. Установите Python, зависимости, `.env`, запустите `python main.py` под systemd/supervisor. Для Windows можно использовать Task Scheduler. Не публикуйте `.env`.

## Лицензия и ответственность

Проект — учебный/практический инструмент. Перед приёмом реальных платежей проверьте законодательство вашей юрисдикции, правила Telegram и налоговые обязанности. Оператор выплат отвечает за реальные переводы продавцам. Бот не является escrow-сервисом и не гарантирует передачу NFT.
